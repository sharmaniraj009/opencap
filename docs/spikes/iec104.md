# IEC 60870-5-104 spike: client driver and server northbound

Spike for [#16](https://github.com/sharmaniraj009/opencap/issues/16), 2026-11-25. It backs
[ADR-0017](../adr/0017-iec104-native-rust-subset.md).

opencap needs IEC 104 in two roles. It acts as a **client** (the controlling station) when it
polls RTUs and substation gateways. It acts as a **server** (the controlled station) when it
serves the tag store to energy SCADA such as zenon or other RTU masters
(`scada-compatibility.md`).

The mature C library, lib60870-C, is GPL-3.0 or commercial. Under ADR-0007 that permits it only
as a separately distributed plugin, and only with the owner's approval.

**Recommendation:** implement the subset natively in Rust: a codec crate, a client driver and a
server north plugin. lib60870 is **not needed in any shipped form**. Use it only as a GPL
test-only peer through c104, installed in CI and never vendored. Add a permissive second peer,
igs-iec104 (Apache-2.0).

A throwaway prototype under [`spikes/iec104/`](../../spikes/iec104/) proves the client subset in
about 330 lines of Python. It runs against both peers and covers STARTDT/STOPDT/TESTFR, general
and counter interrogation, every monitor type in §3, CP56Time2a, the k/w windows and the quality
mapping (§7).

## 3. Needed subset

### 3.1 Client (driver)

- **APCI.**
  - I, S and U frames; 15-bit send and receive sequence numbers.
  - **k = 12** (at most 12 unacknowledged I-frames in flight) and **w = 8** (acknowledge after 8
    received I-frames).
  - **t0 = 30 s** (connect), **t1 = 15 s** (acknowledgement or confirmation timeout),
    **t2 = 10 s** (S-frame delay, t2 < t1) and **t3 = 20 s** (idle → TESTFR).
  - All of these are per-device settings with these standard defaults.
  - A sequence error, or a t1 expiry, closes the connection → `ConnectionLost`.
- **U functions.** STARTDT act/con after connecting; STOPDT before a deliberate close; TESTFR
  in both directions (answer act with con; send act on t3).
- **ASDU** (104 defaults): COT 2 octets (with the P/N and T bits and the originator address),
  common address 2 octets, IOA 3 octets. Sequence (SQ = 1) and non-sequence objects.
- **Monitor types:**

  | Category | Types |
  |---|---|
  | Single points | M_SP_NA_1 (1), M_SP_TB_1 (30) |
  | Double points | M_DP_NA_1 (3), M_DP_TB_1 (31) |
  | Normalized measurands | M_ME_NA_1 (9), M_ME_TD_1 (34) |
  | Scaled measurands | M_ME_NB_1 (11), M_ME_TE_1 (35) |
  | Short float measurands | M_ME_NC_1 (13), M_ME_TF_1 (36) |
  | Integrated totals | M_IT_NA_1 (15), M_IT_TB_1 (37) |
  | End of initialisation | M_EI_NA_1 (70): triggers a GI |

  Later, as needed: step position (5/32), bitstring (7/33), packed single points with status
  change detection (20) and protection events (38–40).
- **Interrogation.**
  - General interrogation C_IC_NA_1 (100) with QOI 20 (station) at start-up, after M_EI_NA_1,
    on reconnect and at the device's GI period. A GI is complete at ACT_TERM.
  - Group interrogation (QOI 21–36) is optional per tag group.
  - Counter interrogation C_CI_NA_1 (101) uses **RQT 5 with FRZ 0 (read)** at the counter
    period. Freeze and reset change the counter, so they are not read-only.
  - The read command C_RD_NA_1 (102) is optional for single tags.
- **Push.** Spontaneous (COT 3) and periodic (COT 1) ASDUs deliver values through the push path
  ([03 §3.3](../architecture/03-deep-dive.md#33-driver-contract)). The driver is a push driver
  whose "read" is the GI. Until the Rust `subscribe` path lands (#46), the latest value per IOA
  is buffered.
- **Read-only framing.** The driver can frame only C_IC_NA_1 and C_CI_NA_1 (FRZ = 0), plus C_RD_NA_1
  if it is added.
  - It cannot frame single, double or regulating-step commands, set points, bitstring commands
    or their time-tagged forms (45–51, 58–64).
  - It cannot frame clock sync C_CS_NA_1 (103), which would write the RTU's clock, reset process
    C_RP_NA_1 (105), parameter loading (110–113) or file transfer (120–127).
  - A unit test pins this (the prototype's `COMMANDS_ALLOWED`).
- **Redundancy groups** (104 Ed. 2): several connections to one station, only one started.
  Switch over on failure, with a GI after each switch-over. This is a later PR (§8.5).
- **TLS** (IEC 62351-3) with rustls, also in a later PR.

### 3.2 Server (north)

- **TCP listener** on 2404 by default, with a configurable list of allowed client IPs and a
  maximum number of connections. Redundancy groups by client IP set.
- **Point map** from the tag store: each mapped tag has a common address, an IOA, a type
  (default by dtype: bool → M_SP, float → M_ME_NC, int → M_ME_NB, counter → M_IT) and a deadband.
- **GI and CI** are answered from the tag store with COT 20 or 37, followed by ACT_TERM.
- **Spontaneous ASDUs** come from the change-event bus (ADR-0005). They use the time-tagged
  variant (TB/TD/TE/TF), with `source_ts` as CP56Time2a.
- **Read-only.**
  - Every command type (45–64), C_RP (105) and P_* (110–113) gets a negative confirmation
    (ACT_CON with P/N = 1). Nothing reaches the tag store or a PLC.
  - An unknown type, COT, CA or IOA gets COT 44, 45, 46 or 47 respectively.
  - A test pins this against both peer clients.
- **Clock sync** C_CS_NA_1 from a master: see §6 Q1.

## 4. Fit with the driver contract

- **plan():** a tag address names a common address and an IOA, with an optional expected
  type. Blocks are per common address: a GI and a CI per station. Addresses cannot be merged
  because the station pushes everything.
- **Errors.**
  - Connect failure, t1 expiry, sequence errors and a dropped connection → `ConnectionLost`.
  - A negative ACT_CON to a GI → `BlockConfigError` (unknown CA, COT 46).
  - A tag whose IOA never arrives after a complete GI → `bad_config` (the plan report names it).
  - A type mismatch (the tag says float, M_SP arrives) → `bad_decode` for that tag.
- **Address syntax:** `<CA>.<IOA>` (for example `47.1001`), with an optional type suffix
  (`47.1001.M_ME_NC_1`). The KEPServerEX "IEC 60870-5-104 Client" syntax must be checked
  against PTC's manual in the import follow-up (§8.6). This spike did not verify it.

## 5. Quality and timestamps (ADR-0006)

### 5.1 IEC 104 quality → opencap (client)

The quality descriptor bits are IV, NT, SB and BL, plus OV for measurands (the QDS octet; the
SIQ and DIQ high bits). Counters (BCR) carry IV, CA and CY.

| Bits | opencap | Why |
|---|---|---|
| IV (invalid) | `bad_decode` | the station says the value is not usable (acquisition fault) |
| NT (not topical) | `stale` | not refreshed within the station's own time limit |
| OV (overflow, measurands) | `bad_decode` | the number is outside its representable range |
| SB (substituted), BL (blocked) | `good` | an operator or a function set or froze the value; it is still "the" value. The flags should be passed through (DNP3 spike §6 Q3) |
| counter CY (carry), CA (adjusted) | `good` | counter events, not quality |
| none | `good` | |

Priority runs from the top: IV, then NT, then OV. The prototype's `quality_of()` is this table.
A lost connection is `bad_comm` through the usual worker path.

### 5.2 Timestamps

- Time-tagged types carry **CP56Time2a**: milliseconds, minutes with an IV bit, hours with the
  SU (summer time) bit, day of month and day of week, month, and two-digit year. That time
  becomes `source_ts`, unless its IV bit is set, in which case the arrival time is used.
- Untagged types use the arrival time.
- The standard does not say whether CP56Time2a is UTC or local time. A device setting
  `time_zone` (default `UTC`; for example `Europe/Berlin` for a station on local time) converts
  it. On local stations the SU bit resolves the autumn hour that occurs twice.
- The client never sends clock sync (read-only, §3.1).

### 5.3 opencap → IEC 104 quality (server)

| opencap | Bits sent |
|---|---|
| `good` | none |
| `bad_comm` | NT + IV (last value) |
| `stale` with a value | NT (last value) |
| never read | IV + NT |
| `bad_config` | IV |
| `bad_decode` | IV (OV as well for a measurand out of range) |

## 6. Questions for the lead

1. **Clock sync from a SCADA master to the opencap server.** Many masters send C_CS_NA_1
   periodically, and some raise an alarm on a negative confirmation. Proposal: answer with a
   positive ACT_CON carrying opencap's own time, and never apply the master's time. This keeps
   opencap read-only toward its own host clock as well. Alternatively, send a negative
   confirmation per configuration.
2. **c104 in CI.** c104 is GPL-3.0. ADR-0007 allows it as a test-only tool installed in CI. To
   keep the default `dev` extra and the licence gate free of GPL, the proposal is a separate,
   path-filtered CI job (`iec104-interop`) that installs `c104==2.2.1` into its own venv. Does
   that need the owner's approval (decision 5 covers *shipping* copyleft plugins, not test
   tools)?
3. **Flag pass-through.** Same as DNP3 spike §6 Q3: SB/BL (and IV/NT/OV) would survive end to end
   if the tag store kept protocol flags.

### 7.1 Simulator and CI plan

`tests/helpers/iec104_sim.py` (follow-up 2) is a pure-Python IEC 104 server with our own APCI and
ASDU code. A server sim must be our code, because no permissive Python stack exists.

- **Stations:** several common addresses; points of every §3.1 type; values, quality and time
  per point; spontaneous and periodic transmission.
- **Fault switches:**
  - `mute` (no replies; t1 expires on the client);
  - `drop_connection`;
  - `no_startdt_con`;
  - `bad_sequence` (send an out-of-order N(S));
  - `withhold_ack` (no S-frames, so the client hits k);
  - `negative_gi` (unknown CA);
  - `slow_gi` (ACT_TERM late);
  - `restart()` (M_EI_NA_1 after a reconnect).
- **Counters:** `commands` (every C_* other than C_IC/C_CI/C_RD, answered negatively and
  counted), `gi_count` and `ci_count`.

It is validated, unmodified, by the **c104 client** (lib60870, GPL, test-only) and the
**igs104-client** (Apache-2.0).

The c104 validation runs in a separate path-filtered CI job (§6 Q2). The igs104 validation needs
the binary: CI builds it once with `cargo install` and caches it. The opencap IEC 104 **server**
north is accepted against the same two clients (SCADA matrix L1).
