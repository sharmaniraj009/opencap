# Omron FINS conformance vectors

These are language-neutral vectors for the FINS driver (ADR-0014; the Rust driver is #54). The
protocol notes are in
[`docs/protocols/omron-fins.md`](../../../docs/protocols/omron-fins.md); §5 there describes the
syntax.

## `addresses.json`: KEPServerEX Omron FINS address syntax (CS1/CJ1/CJ2)

Each entry is written by hand from PTC's *Omron FINS Ethernet Driver* manual (v1.083, the
CS1/CJ1/CJ2 addressing tables) and Omron W342 5-2-2 (the area codes). None is generated by a
parser.

```json
{
  "valid":   [{"address": "D100", "dtype": "float32", "words": 2,
               "expect": {"area_code": "0x82", "word": 100, "bit": null, "kind": "word"}}],
  "invalid": [{"address": "D32767", "dtype": "float32", "why": "a 32-bit value needs D32767 and D32768"}]
}
```

Fields:

- **`model`:** `CS1`, `CJ1` or `CJ2`; `CJ1` when absent. The ranges differ by model. Only CJ2
  has A960–A1471, A10000–A11535, EM banks 13–24 and TK32–TK127.
- **`dtype`:** the tag's data type, as an opencap name. KEPServerEX types map as Boolean `bool`,
  Short `int16`, Word `uint16`, Long `int32`, DWord `uint32`, Float `float32`, BCD `bcd16`,
  LBCD `bcd32` and String `string`. When absent, the address's KEPServerEX default applies:
  Word; BCD for `T` and `C`; DWord for `IR`; Boolean for bits and flags.
- **`expect.area_code`:** the FINS memory area code that a read of this address uses, as a hex
  string.
  - Word addresses use the word code, and bit addresses the bit code.
  - Flags use the flag code: completion flags (`TS`, `CS`) use `0x09`, task flags (`TK`) use `0x06`.
  - The current EM bank (`E<n>`) uses `0x98` (bit `0x0A`).
- **`expect.word`:** the FINS word address sent in the command, as it appears on the wire.
  Counter *n* is `0x8000 + n`, `IR`*n* is `0x0100 + n` and `DR`*n* is `0x0200 + n`.
- **`expect.bit`:** 0–15 for a bit address, otherwise `null`.
- **`expect.kind`:** one of `word`, `bit`, `flag` or `string`.
- **`expect.dims`:** the array dimensions (`D100[4]` gives `[4]`, `D100[2][3]` gives `[2, 3]`).
  Absent when the address is not an array.
- **`expect.str_len`, `expect.str_order`:** for strings, the length in characters and the order.
  `H` and `L` hold two characters per word, high or low byte first. `D` and `E` hold one
  character per word, in the high or low byte.
- **`expect.bcd`:** `true` for the `D` suffix (`D0D`). A Word or DWord is then unsigned BCD, and
  a Short or Long signed BCD.
- **`words`:** how many elements a read of this tag covers. That is words for word areas,
  1 for bits, flags and an index register (one 4-byte element), and the words spanned for a
  string. A planner must request at least this many elements, starting at `word`.

Every `invalid` entry must be refused. It may carry a `dtype` (for example, a 32-bit value that
runs past the end of an area) and a `model`. The entries include `E0_100` and `EM100`: those
spellings appear in Omron's own manuals and in some tools, but they are not KEPServerEX syntax.

`tests/unit/test_fins_sim.py` checks every vector against the simulator's own parser
(`tests/helpers/fins_sim.py: parse_address`), which shares no code with any driver. A Rust
driver test must produce the same `area_code`, `word`, `bit`, `kind`, `dims`, `str_len`,
`str_order`, `bcd` and `words` for every valid vector, and must reject every invalid one.
